\section{Sformułowanie zadania}

Celem zadania była implementacja i przebadanie metaheurystyki Algorytmu Ewolucyjnego (EA)
dla \textit{Capacitated Vehicle Routing Problem with Time Windows} (CVRPTW) -- pojemnościowego
problemu wyznaczania tras pojazdów z oknami czasowymi.

W CVRPTW rozpatrywano $n$ klientów i $K$ pojazdów o jednakowej pojemności $Q$.
Każdy klient $i$ posiadał: lokalizację $(x_i, y_i)$, zapotrzebowanie $d_i$, okno czasowe
$[e_i, l_i]$ (najwcześniejszy i najpóźniejszy dozwolony czas obsługi) oraz czas obsługi $s_i$.
Poszukiwano zestawu tras minimalizującego \textbf{łączną długość przejechanych tras} przy
spełnieniu ograniczeń pojemności i okien czasowych.

Penalizacja była dodawana za:
\begin{itemize}
    \item zbyt późne przybycie do klienta ($> l_i$): kara proporcjonalna do opóźnienia,
    \item zbyt wczesne przybycie ($< e_i$): pojazd czeka bez kary (EARLY\_ARRIVAL\_PENALTY = 0).
\end{itemize}

% ─────────────────────────────────────────────────────────────────────────────
\section{Sposób rozwiązywania zadania}

\subsection{Kodowanie rozwiązania}

Rozwiązanie kodowane było jako permutacja liczb całkowitych o długości
$\texttt{SIZE} + \texttt{MAX\_VEHICLES} - 1$.
Wartości $0 \ldots \texttt{SIZE}-1$ oznaczają klientów, a wartości $\geq \texttt{SIZE}$
są symbolami \emph{powrotu do bazy} (separatorami tras).

Przykładowo dla $n=5$ klientów i 3 pojazdów:
\[
  x = [3,\ 1,\ \mathbf{5},\ 0,\ 4,\ \mathbf{6},\ 2]
\]
oznacza: trasa 1: $\{3, 1\}$, trasa 2: $\{0, 4\}$, trasa 3: $\{2\}$.

\subsection{Ocena rozwiązania}

Funkcja \texttt{EstimateSolution} symuluje przejazd każdego pojazdu:
\begin{enumerate}
    \item Pojazd startuje z bazy w czasie $t=0$ z pełną pojemnością.
    \item Dla każdego klienta na trasie: aktualizowany jest czas przyjazdu,
          uwzględniane jest oczekiwanie na otwarcie okna, dodawana jest kara za
          spóźnienie, odejmowane jest zapotrzebowanie.
    \item Koszt to suma odległości euklidesowych plus sumaryczna kara.
\end{enumerate}

\section{Metody użyte do rozwiązania zadania}
\begin{itemize}
  \item Algorytm ewolucyjny (EA) z operatorami standardowymi (krzyżowanie + mutacja swap/inverse)
  \item Algorytm ewolucyjny z dodatkowymi operatorami niestandardowymi:
        \textbf{Repair}, \textbf{OptimizeTracks}, \textbf{RedistributeLocations}
\end{itemize}

% ─────────────────────────────────────────────────────────────────────────────
\section{Implementacja}

\subsection{Algorytm ewolucyjny (EA)}
\label{sec:ea}
\begin{itemize}
    \item \textbf{Inicjalizacja:} populacja losowych permutacji (rozmiar \texttt{popSize}).
    \item \textbf{Selekcja:} turniejowa -- losowano \texttt{turSize} osobników, wybierano najlepszego.
    \item \textbf{Krzyżowanie:} OX (\textit{Ordered Crossover}) lub PMX/CX; stosowane z prawdopodobieństwem \texttt{Xp}.
    \item \textbf{Mutacja:} SWAP (zamiana dwóch losowych genów) lub INVERSE (odwrócenie segmentu);
          stosowana z prawdopodobieństwem \texttt{Mp}.
    \item \textbf{Elityzm:} \texttt{elitesNum} najlepszych osobników przechodzi do kolejnego pokolenia bez zmian.
    \item \textbf{Kryterium zatrzymania:} po wykonaniu ustalonego budżetu ewaluacji $B$.
\end{itemize}

\subsection{Operatory niestandardowe}
\label{sec:custom_ops}

\paragraph{Repair.}
Po mutacji przeskanuj osobnika. Klientów, którzy naruszają okna czasowe
(przybycie $> l_i$), wytnij z trasy i wstaw w możliwe miejsca innych tras gdzie
ograniczenie jest spełnione. Operator zwiększa dopuszczalność rozwiązania bez
zmiany ogólnej struktury permutacji.

\paragraph{OptimizeTracks.}
Dla każdej trasy osobno uruchom lokalną optymalizację kolejności klientów
(greedy insertion lub przeszukiwanie $k$-opt). Operator poprawia koszt wewnątrz
trasy bez przenoszenia klientów między trasami.

\paragraph{RedistributeLocations.}
Wybierz losową trasę-dawcę i losowego klienta; spróbuj przenieść go na
każdą możliwą pozycję w innej trasie (biorcy). Jeśli ruch obniża koszt
i nie narusza pojemności~-- zaakceptuj. Operator optymalizuje podział klientów
między trasami.

\subsection{Kontrola budżetu}
Budżet wyrażony jest w liczbie ewaluacji funkcji celu:
$B = \texttt{loops} \times \texttt{popSize}$,
gdzie \texttt{loops} to liczba pokoleń.
Stosowano dwa budżety:
\begin{itemize}
    \item Strojenie: $B = 100 \times 100 = 10\,000$ (szybkie iteracje).
    \item Porównanie końcowe: $B = 100 \times 100 \times 20 = 200\,000$.
\end{itemize}

\section{Procedura badawcza}
\begin{itemize}
    \item Budżet strojenia: $B = 10\,000$ wywołań funkcji celu dla wszystkich konfiguracji.
    \item Budżet porównania końcowego: $B = 200\,000$.
    \item Liczba powtórzeń: $N = 5$ niezależnych uruchomień.
    \item Miara jakości: \textbf{średnia} (avg) wyników z $N$ powtórzeń.
    \item Parametry bazowe: \texttt{popSize=50}, \texttt{Xp=75}, \texttt{Mp=25},
          \texttt{turSize=2}, \texttt{elitesNum=1}, krzyżowanie OX, mutacja SWAP.
    \item Operatory niestandardowe (wariant ON): \texttt{REPAIRp=70}, \texttt{OPTp=30}, \texttt{REDISTp=80}.
\end{itemize}

\section{Analiza wyników i wnioski}
\label{sec:conclusions}

\subsection{Wpływ operatorów niestandardowych}

Operatory niestandardowe konsekwentnie poprawiały wyniki we wszystkich instancjach
i przy obu budżetach. Największy efekt zaobserwowano dla C101 (klastry):
operatory umożliwiły podział klientów w klastrach na wydajne trasy.
Dla R101 (losowy) poprawa była mniejsza -- losowe rozmieszczenie klientów utrudnia
lokalną optymalizację tras.

Wariant z operatorami osiągnął wynik bliski BKS dla RC101 (gap $= -0{,}5\%$,
tj.\ nieznacznie poniżej wartości tabelarycznej, co może wynikać z zastosowanej
penalizacji zamiast twardych ograniczeń). Dla C101 duży gap ($92{,}7\%$) wskazuje,
że instancje klastrowe wymagają większego budżetu lub dedykowanych metod inicjalizacji.

\subsection{Kluczowe obserwacje}

\begin{enumerate}
    \item \textbf{Operatory niestandardowe mają decydujący wpływ} -- poprawa
          $25$--$28\%$ już przy małym budżecie strojenia, $4$--$13\%$ przy
          pełnym budżecie. Są ważniejsze niż dobór \texttt{Xp} czy \texttt{Mp}.
    \item \textbf{Zbyt duża populacja szkodzi} -- przy stałym budżecie więcej
          osobników oznacza mniej pokoleń; operatory niestandardowe potrzebują
          iteracji, żeby efektywnie poprawiać trasy.
    \item \textbf{Wariant z operatorami jest bardziej stabilny} -- niższe
          odchylenie standardowe (RC101: std=50 z operatorami vs 103 bez).
          Operatory pełnią rolę lokalnego naprawiacza, zmniejszając zmienność losową.
    \item \textbf{Strojenie parametrów \texttt{Xp} i \texttt{Mp} przyniosło
          marginalną poprawę} -- przy $N=5$ różnice są w granicach szumu
          statystycznego. Ważniejszy jest sam fakt włączenia operatorów
          niestandardowych.
\end{enumerate}
